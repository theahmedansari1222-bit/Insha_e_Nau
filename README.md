# انشائے نو

نئے لکھاریوں کی اردو تحریروں کا پلیٹ فارم۔ ٹیک: `Astro` + `Cloudflare` + `Supabase`۔
**ورژن 1.0:** پڑھنے والی سائٹ، لکھاری کا فارم اور نجی لنک، ایڈمن پینل، رابطہ، پسند، اشتہار کی جگہ۔

## 1) پہلی بار سیٹ اپ (ترتیب سے)

### سپابیس
1. نیا پروجیکٹ بنائیں۔ `SQL Editor` میں پہلے `supabase/001_tables.sql`، پھر `supabase/002_security.sql` چلائیں۔
2. `Project Settings → API Keys` سے تین چیزیں نوٹ کریں: پروجیکٹ کا پتا، عوامی (publishable) کنجی، خفیہ (secret) کنجی۔
3. **ایڈمن کا اکاؤنٹ:** `Authentication → Users → Add user → Create new user`۔ ای میل اور پاسورڈ لکھیں اور `Auto Confirm User` لگا رہنے دیں۔
4. (بہتر) `Authentication` کی سیٹنگز میں نئے صارفین کی خود رجسٹریشن بند کر دیں۔

### کوڈ میں دو جگہ
- `wrangler.jsonc` میں `SUPABASE_URL` اور `SUPABASE_PUBLIC_KEY` (عوامی کنجی محفوظ ہے)۔
- اسی فائل میں `ADMIN_EMAILS` کی جگہ وہی ای میل لکھیں جو آپ نے ایڈمن کے لیے بنائی۔ ایک سے زیادہ ہوں تو کاما سے الگ کریں۔

### کلاؤڈ فلیئر
1. `Workers & Pages` → نیا پروجیکٹ → گِٹ ہب ریپو جوڑیں۔ Build command: `npm run build`، Deploy command: `npx wrangler deploy`۔
2. بلڈ نہ چلے تو `Settings → Build` میں `NODE_VERSION` کی قدر `22` رکھیں۔
3. **خفیہ کنجی:** ورکر → `Settings → Variables and Secrets` → `Add` → قسم `Secret` → نام `SUPABASE_SECRET_KEY` → سپابیس کی secret کنجی → `Deploy`۔ یہ کنجی کسی فائل، گِٹ ہب یا چیٹ میں نہ جائے۔
4. **ڈومین:** ڈومین کلاؤڈ فلیئر پر ہو تو ورکر → `Settings → Domains & Routes → Add → Custom domain` میں `inshaenau.com` لگائیں۔
5. (اختیاری) جعلی بھرتی روکنے کے لیے `Turnstile` کی سائٹ بنا کر `TURNSTILE_SITE_KEY` کو `wrangler.jsonc` میں اور `TURNSTILE_SECRET` کو `Secret` کے طور پر ڈالیں۔

(مینو کے نام وقت کے ساتھ تھوڑے بدل سکتے ہیں۔)

## 2) نیا زپ لگانا (ٹرمکس میں، ایک ہی بار میں پش)

```
cd ~
rm -rf inshaenau-new
unzip -q ~/storage/downloads/نئے_زپ_کا_نام.zip -d inshaenau-new
cp -r inshaenau-new/inshaenau/. inshaenau/
cd inshaenau
git add -A
git commit -m "اپ ڈیٹ"
git push
```

## 3) روزمرہ کا استعمال

- **ایڈمن:** `/admin` پر لاگ اِن کریں۔ چار حصے ہیں: تحریریں، لکھاری، صفحات، پیغامات۔
- **نئی تحریر آئے تو:** تحریریں میں "زیرِ جائزہ" کھولیں۔ ضرورت ہو تو متن ایڈٹ کریں، پہلی بار والے لکھاری کا **ہینڈل** لکھیں (انگریزی چھوٹے حروف، مثلاً `mahnoor`)، پھر فیصلہ:
  - **منظور اور شائع کریں:** تحریر سائٹ پر آ جاتی ہے۔
  - **تبدیلی مانگیں:** نوٹ لکھنا ضروری ہے۔ لکھاری اپنے نجی لنک پر نوٹ دیکھ کر ترمیم کر کے دوبارہ بھیج سکتا ہے۔
  - **مسترد کریں:** وجہ لکھنا ضروری ہے۔
  - **بڑی تبدیلی:** خانہ لگا کر نوٹ لکھیں۔ شائع ہونے کے بعد بھی لکھاری کو نجی لنک پر دکھے گا۔
- **لکھاری کو بتانا:** تحریر کے صفحے پر "جی میل میں کھولیں" دبائیں۔ پیغام اور نجی لنک پہلے سے لکھا ہوا کھلے گا، آپ بھیج دیں۔
- **صفحات:** ہمارے بارے میں، اشاعت کے اصول، پرائیویسی، شرائط کا متن "صفحات" میں لکھ کر "شائع" کریں۔ نئے صفحے بھی یہیں بنتے ہیں۔
- **اصل تحریر ہمیشہ محفوظ** رہتی ہے۔ ایڈٹ والے صفحے پر "لکھاری کی اصل تحریر دیکھیں" میں نظر آتی ہے۔

## 4) اشتہار (جب منظوری مل جائے)

1. پہلے سائٹ پر ضروری صفحے شائع کریں: ہمارے بارے میں، رابطہ، پرائیویسی، شرائط، اشاعت کے اصول۔
2. گوگل ایڈسینس میں سائٹ جمع کرائیں۔ منظوری کے بعد `wrangler.jsonc` میں `ADSENSE_CLIENT` (جیسے `ca-pub-...`) اور تحریر کے نیچے والے اشتہار کا `ADSENSE_SLOT_ARTICLE` لکھیں۔
3. دونوں خالی ہوں تو سائٹ پر نہ اشتہار آتا ہے نہ جگہ گھرتی ہے۔
4. یاد رہے: کوکی کی رضامندی کا بینر ابھی شامل نہیں۔ یورپ و برطانیہ کے قارئین ہوں تو بعد میں لگانا پڑے گا۔

## 5) مفت پلان: احتیاطیں

- **سپابیس کا مفت پروجیکٹ ایک ہفتہ سرگرمی نہ ہو تو رک جاتا ہے۔** `.github/workflows/keepalive.yml` ہر تین دن بعد ہوم پیج کھول کر اسے جگائے رکھتا ہے۔ ڈومین ابھی نہ لگا ہو تو گِٹ ہب ریپو میں `Settings → Variables → Actions` میں `SITE_URL` کی قدر اپنے ورکر کا پتا رکھیں۔
- **مفت پلان میں خودکار بیک اپ نہیں۔** ایڈمن کی تحریریں والی فہرست کے آخر میں "بیک اپ ڈاؤن لوڈ کریں" کا لنک ہے۔ ہفتے میں ایک بار فائل محفوظ کر لیں۔
- ڈیٹا بیس اور تصاویر کی جگہ محدود ہے۔ اسی لیے تصاویر فون ہی میں چھوٹی ہو کر اپلوڈ ہوتی ہیں۔ حد قریب آئے تو سپابیس کا ادا شدہ پلان سب سے پہلا خرچ ہو۔

## 6) خرابی ہو تو

| علامت | وجہ اور حل |
|---|---|
| ہوم خالی ہے | SQL فائلیں نہیں چلیں، یا `wrangler.jsonc` میں پتا/کنجی غلط ہے |
| تحریر بھیجنے پر "قبول نہیں ہو سکی" | `SUPABASE_SECRET_KEY` کلاؤڈ فلیئر میں نہیں ڈالی |
| ایڈمن میں "ڈیٹا بیس سے رابطہ نہیں ہو سکا" | وہی: خفیہ کنجی |
| لاگ اِن نہیں ہوتا | `ADMIN_EMAILS` میں وہی ای میل نہیں، یا سپابیس میں صارف کنفرم نہیں |
| تصویر اپلوڈ نہیں ہوتی | `002_security.sql` نہیں چلی (تصاویر کا ذخیرہ نہیں بنا) |
| بلڈ ناکام | `NODE_VERSION` کو `22` رکھیں |

## 7) ڈھانچہ

```
src/pages/       صفحے (ہر فائل ایک پتا)
  admin/         ایڈمن پینل
  api/           پس منظر کی درخواستیں (فارم، تصویر، ایڈمن کارروائیاں)
src/components/  چھوٹے اجزا
src/layouts/     مشترک ڈھانچہ
src/lib/         مددگار کوڈ (ڈیٹا، اردو کی صفائی، محفوظ متن، لاگ اِن)
src/styles/      ڈیزائن
src/middleware   ایڈمن کی حفاظت اور مختصر کیش
supabase/        ڈیٹا بیس کی فائلیں
public/          جوں کی توں جانے والی فائلیں
```

## 8) معلوم کمیاں (بعد کے لیے)

- فونٹ گوگل سے آ رہے ہیں؛ اپنے سرور پر رکھنے سے مزید تیز ہوں گے۔
- شائع کرنے کا وقت مقرر کرنا (شیڈول) نہیں۔
- سائٹ میپ میں ہزار تحریروں تک کی گنجائش ہے؛ زیادہ ہوں تو تقسیم کرنا ہو گی۔
- خودکار ای میل نہیں؛ اطلاع ایڈیٹر جی میل سے خود بھیجتا ہے۔
- اپلوڈ ہو کر استعمال نہ ہونے والی تصاویر کی خودکار صفائی نہیں۔
